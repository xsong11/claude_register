# Codex Proxy RS 账号与代理对接设计

状态：方案待选，未进入实现。接口依据为本机 CPR `v3.39.1`（`12c32fcd`）源码及随附文档，未连接实际部署。本文中的本地页面、存储和流程均为设计。

## 1. 目标与范围选项

在 claude-register 中配置 CPR 服务地址和管理员 API 密钥，查看 CPR 的账号、出站代理及绑定关系。后续可按需要选择远程管理、把本地账号或代理推送到 CPR，以及凭据维护。各项可单独交付；「刷新列表」只回读 CPR，「推送」才把本地数据写入 CPR。

| 可选范围 | 用户可以做什么 | 依赖与影响 |
| --- | --- | --- |
| A · 远程查看 | 检查连接、搜索账号和代理、查看状态、绑定、额度快照及已有检测结果 | 只读管理接口；不写本地账号库或 CPR |
| B1 · 远程账号管理 | 启停调度、改绑或解除绑定；可选分组、权重和并发设置 | 依赖 A 的查询；影响 CPR 调度及出口 |
| B2 · 远程代理管理 | 新建、更新、启停及测试 CPR 代理；查看受影响的账号 | 依赖 A 的查询；改连接配置会影响所有绑定账号 |
| C1 · 本地代理推送 | 从本地代理池选取代理，关联已有 CPR 代理或在 CPR 新建 | 需要目标映射；推送认证信息前展示目标和影响 |
| C2 · 本地 ChatGPT 账号推送 | 从本地账号库挑选账号和目标代理，预览后导入 CPR | 需核对身份、凭据来源和续期能力；导入接口会更新已有身份 |
| D · 凭据维护 | 在 CPR 主动刷新额度或 OAuth；在本地会话检测后按需重新授权 | 三种动作各自触发；凭据续期由持有对应凭据的一端负责 |

建议先选 A；若需要在面板内直接操作，优先叠加 B1。C1 可独立于 C2 启用。C2 如果以长期运行和自动续期为目标，应先确定使用 CPR OAuth 还是新增受支持的 Codex OAuth 凭据来源。定时推送、双向写回、自动删除及密钥导出不属于默认范围。

## 2. 数据归属

| 数据 | 权威来源与同步规则 |
| --- | --- |
| 本地注册、检测、领取、账号状态 | claude-register。CPR 的限流、停用或额度耗尽不修改本地状态 |
| CPR 调度状态、分组、代理绑定、额度及连通性 | CPR。面板按需回读；远程动作显式写 CPR，并重新读取结果 |
| 本地代理池与 CPR 出站代理 | 各自管理。只手动选择建立映射或推送；本地节点变更、删除、到期不自动改 CPR |
| 浏览器会话和凭据 | 本地保留登录密码、Session Token、邮箱凭据及会话 JSON；CPR 只收到选定的 Codex 认证材料，正常回读不取任何凭据 |

CPR 的管理员密钥权限覆盖部署级管理接口。对接页面即使只读，密钥本身仍有写权限。若实际需求只是匿名池规模、额度窗口或模型可用性，可以改用 CPR 的 `/cpr/link` 和授权范围受限的推理 Key；该协议不提供具体账号、代理管理或绑定写入。

## 3. 设置与安全边界

- 「系统设置 → Codex Proxy RS 对接」提供实例名称、服务地址、管理员 API 密钥、测试连接、替换密钥和断开连接。可先只展示一个实例；本地记录仍用 `instance_id` 区分来源，为以后并列多个实例留空间。管理员密钥在 CPR 的运行设置生成；如果 CPR 已有密钥但原值没有保留，重新生成会使旧密钥失效，应在 CPR 侧安排轮换。
- 浏览器只调用 claude-register 同源接口。面板服务端固定调用 CPR 的已知路由，并在 `x-api-key` 头附上密钥。复用现有面板登录鉴权；安装引导状态和 `/api/v1/*` 开放 API Key 均不能配置或调用该对接。页面不能传入要代理的任意 URL、路径或请求头。
- 服务地址支持域名、端口和反代前缀，规范化后存储，禁止 URL 用户信息、查询参数和片段。跨主机部署默认 HTTPS，保留证书校验；可信私网或回环的 HTTP 作为显式例外。配置变更、测试和读取都用同一校验；不跟随跳转、不自动经系统代理转发管理员密钥。地址变化必须重新输入密钥，旧实例的映射不转移到新地址。
- 建议用独立的 SQLite 连接记录保存密钥密文，复用当前项目已有的 AES-GCM 方式，使用与其他功能不同的派生上下文，并把实例 ID 和规范化地址绑定为附加验证数据。加密密钥来自面板本地 `secret.key`；部署备份需分别保护数据库和该文件。界面只回传是否配置，留空保存原密钥仅适用于同一地址；断开只删除本地保存的密钥，不撤销 CPR 密钥。
- 连接测试用 `GET /api/admin/accounts?page=1&pageSize=1` 验证管理权限，再探测代理列表端点，记录各自能力。CPR 的 HTTP 401/403 表示远端密钥问题，不能当成面板登录失效。对外响应使用固定提示及安全的请求 ID，不回传远端错误原文、完整代理地址、Token、会话 Cookie 或包含这些数据的任务输入。列表、测试及写操作响应使用 `Cache-Control: no-store`。

## 4. 页面和远端接口

建议侧栏新增「CPR 管理」，包含「账号」「代理」两个列表；选定 C 后再加「推送」和「历史」。页面显示当前实例及最近读取时间。进入页面、切换筛选或点「刷新列表」时按页查询 CPR。失败时标明不可用；若保留上次数据显示，明确标为旧数据，不能用来提交操作。远端分页透传页码和筛选，面板只投影要展示的字段。A 不必建立账号或代理本地镜像，也不自动轮询上游额度。

| 页面功能 | CPR 路由（均在 `/api/admin` 下） | 用法和边界 |
| --- | --- | --- |
| 账号列表、详情 | `GET /accounts`、`GET /accounts/detail` | 展示名称、邮箱、平台、套餐、调度开关、运行状态、分组和出站代理。额度、并发为 CPR 提供的观测值，缺失显示未知 |
| 代理列表及账号 | `GET /proxies`、`GET /proxies/accounts` | 展示脱敏地址、启用状态、位置、绑定账号数及最近检测，支持按代理查看绑定账号 |
| 账号局部更新 | `POST /accounts/batch-update`、`GET /account-groups/options` | 单条也可传一个 `accountIds`；只提交要改的字段，避免完整表单覆盖并发变化。改分组前展示完整分组差异 |
| 解除账号绑定 | `POST /proxies/accounts/remove` | 对现有受管绑定优先使用 `{proxyId, accountId}`，CPR 会校验账号仍绑定该代理。解除后改为直连 |
| 代理写入与检测 | `POST /proxies/create`、`/proxies/update`、`/proxies/test` | 创建和检测按条返回结果；更新、检测使用该代理的 `revision`，409 时重新读取。测试失败是检测结果，不等于提交失败 |
| 导入账号 | `POST /accounts/import`、`/accounts/import-tasks` | 小批量按账号拆分；长任务使用 CPR `submissionId` 和任务状态回读，记录返回的账号 ID |
| 额度和凭据维护 | `GET /accounts/quota`、`POST /accounts/quota/refresh`、`POST /accounts/refresh`、`POST /accounts/oauth/start` 与 `/complete` | 分开呈现「查看额度快照」「刷新额度」「刷新 OAuth」「重新授权」。读快照不发起上游请求；OAuth 回调沿 CPR 原生流程 |

账号行的「停用」是 `enabled=false`，暂停调度并保留凭据。重新启用不清除限流、错误或额度记录；不把 `/accounts/recover` 当作通用启用按钮，因为对已启用账号它会清除 CPR 的错误和冷却状态。若以后提供强制恢复，需单独命名并说明含义。

账号绑定写入用 `outboundProxyId` 选择已启用的 CPR 代理；不能同时提交代理 ID 和 URL。禁用 CPR 代理会保留绑定，但关联账号的新请求改为直连；解绑、禁用以及未来若支持的删除操作，必须预览受影响账号和直连后果。已配置且启用的代理连不通时，CPR 不回退直连。默认不提供账号删除和代理删除，若之后选中，应单独设计影响预览和确认。

面板内部接口建议放在 `/api/cpr`，按能力添加，不做通用转发。A 可用 `GET /connections` 返回实例摘要，`POST /connections/test` 校验待保存地址及密钥，保存/断开分别走独立设置请求；`GET /connections/{id}/accounts`、`/proxies` 及详情查询返回 `{items, page, observed_at}` 或对应详情。选中写入功能后，可提供独立的账号设置、代理设置及导入动作；涉及批量或出口变更时，先返回 `preview_id` 和逐条差异，提交时携带 `preview_id`，进度接口只返回可显示结果。服务端按已选功能限制可执行动作；页面隐藏入口只是展示规则。

凭据维护中，「本地重新检测」只更新本地会话与状态；「CPR 重新授权」使用对应 CPR 账号 ID 启动原生 OAuth，回调按同一实例、同一账号完成后再回读结果。可先从面板跳转 CPR 完成授权。若以后在面板内接收回调，授权地址与回调数据只在流程内短时使用，不写审计或操作历史。

## 5. 本地 → CPR：预览、匹配、提交

### 代理

1. 从本地代理池选择已保存代理。标准 HTTP、HTTPS、SOCKS5、SOCKS5H 进入候选，其他协议或不适合跨主机使用的本地地址标记原因；实际连通性由 CPR 所在网络测试。凭据仅从服务端读取，预览只显示脱敏地址。
2. 已有可靠映射时检查 CPR 代理是否仍存在，且准备绑定时是否启用。没有映射时可人工选择已有 CPR 代理，也可按本地代理地址新建。远端列表只有脱敏端点，相同地址端口无法证明代理认证相同；不会按名称或端点自动复用。新建接口返回重复或请求结果未知时，回读目录，让用户核对后关联。
3. 创建成功后保存 `(instance_id, local_proxy_id, remote_proxy_id)`；不会自动将后续本地修改推到 CPR。若支持「更新已映射代理」，先读取最新 revision、显示受影响的账号并确认；代理选项和凭据必须由该动作明确指定。代理创建与后续账号导入分开提交，后者失败时保留已建代理和可重试映射。

### 账号

1. 候选来源为本地 ChatGPT 账号库。处于待检测、停用、封禁、检测失败或缺少可用凭据的账号默认不可推送；Claude 账号、邮箱密钥、浏览器 Cookie 和 Session Token 不进入 CPR 导入请求。保存的会话 `chatgpt_account_id` 在缺少 `account.id` 时可能是 `user.id`，因此不能直接当作已验证工作区 ID。
2. 以 **CPR 实例 + CPR 账号 ID** 保存显式关联。首次匹配依据可验证的 `(provider, upstream user ID, upstream account/workspace ID)`；按 CPR 的身份规则处理空工作区值。规范化邮箱只给出候选，重名、同邮箱多工作区、身份缺失或不一致一律不自动关联或覆盖。CPR 的 OAuth 普通导入会从 ID Token、Access Token 提取身份，手填的顶层 `userId/accountId` 不能改变导入目标。使用会话 AT 前必须确认该版本可提取预期身份，并通过真实环境的隔离账号验证兼容性。
3. 预览逐条标记「可新建」「已存在，可关联」「身份待核对」「令牌将过期或无法续期」及目标代理。计划绑定时以 CPR 代理 ID 为准；没有选代理时明示目标出口，不能因匹配失败而悄悄直连。导入默认不启用调度时必须显式提交 CPR 要求的 `settings`（`enabled=false`、继承并发、确认过的权重和分组），启用由后续独立动作完成。
4. 本地现有 ChatGPT 流程不获取 Codex OAuth Refresh Token。AT-only 在 CPR 可接受的前提下可做临时导入；已知过期会被拒绝，无刷新令牌就不能靠 CPR 自动续期。长期账号优先由 CPR 完成 Codex OAuth 并关联本地记录。后续若增加正规的 Codex OAuth 凭据来源，再单独设计 `accessToken`、`refreshToken`、`idToken` 的导入；同一份会轮换的 Refresh Token 只由一个系统持有并负责刷新。
5. 导入前立即重读本地凭据和状态、远端身份与代理，失效或有变更则回到预览。CPR 普通导入按上游身份新增或更新，已匹配时可替换凭据、重置额度和错误观测，并更新启用等字段；省略设置也不是「只替换令牌」。现有账号应优先走原生重新授权；默认不允许 AT-only 覆盖已有可续期凭据。当前核实的导入合同没有「仅当不存在才创建」的前置条件：如果必须严格保证不覆盖，需 CPR 提供原子的仅创建或预期版本语义，否则暂不开启该写入；提交前检查只能缩短竞争窗口。
6. 只有 CPR 返回确认提交的账号 ID 并校验身份后才写入本地映射。若任务响应丢失，用同一 `submissionId` 和原始输入查询或重提同一任务（仅在 CPR 保留期内且输入完全一致），并回读远端目录；凭据、输入或目标已变更时不能复用该 ID。超时、进程重启或任务过期后的结果未知，应先核对，不自动重发导入或令牌交换。

## 6. 本地存储、并发与错误处理

| 数据 | 何时需要 | 建议存什么 |
| --- | --- | --- |
| `cpr_connections` | A 起 | 实例 ID、名称、地址、密钥密文及更新时间。地址和密钥变更使用本地版本，进行中的写入固定实例和目标地址 |
| `cpr_account_links` / `cpr_proxy_links` | C 起，或明确需要对照 | 实例 ID、本地工作区记录/代理 ID、CPR 记录 ID、关联时间；同一实例内两侧 ID 各自唯一。外部记录不存在标记断链，重新关联由用户处理 |
| `cpr_operations` | 开启写操作后 | 操作、目标 ID、时间、发起者标识（若面板可提供）、已知结果和 CPR 请求/任务 ID；不存原始请求体、密钥、Token 或代理认证 |

写入采用「预览 → 明确提交 → 回读」：预览短期有效且绑定到实例和所选字段；本地对同实例同目标避免重复并发写入。代理使用 CPR 的资源 revision；账号批量更新没有同等的条件版本，按字段提交并在写入前重读对比，仍可能与 CPR 后台的同时修改冲突。把成功、失败、跳过和结果未知分开显示。批次部分成功时保留已生效操作，不能把整批当成失败后重发。仅对明确无副作用的查询做有界重试；写入超时先回读，401/403 提示密钥，404 区分记录不存在与接口不支持，409 提示重读并确认差异，429 允许稍后主动再试。

如选定自动同步，另行确定对象、方向、时段及失败停机策略。默认只允许周期性回读或提醒差异；定时覆盖账号凭据、删除、自动改绑和无感降级为直连均不从手动方案继承。

## 7. 验收与待选项

- A：用模拟 CPR 校验鉴权、分页、筛选、两类列表、脱敏、未配置、无效密钥、超时与旧版本。浏览器验证设置、连接测试、刷新及断开；隔离 CPR 用只读请求验证实际版本。检查 OpenAI、sub2api、本地账号库和代理池照常工作。
- B：用隔离实例验证停用不改变凭据、账号局部更新不覆盖无关字段、代理绑定冲突、禁用/解绑改直连的预览、检测部分失败和过期 revision。验证远程失败不会误写本地状态。
- C：覆盖同邮箱不同工作区、AT-only、过期凭据、已有可续期账号、同端点不同认证、远端超时后其实已提交、任务部分成功、连接更换和断链。真实验证使用专用账号和代理，不使用生产账号试导入。
- D：分别验证查询额度快照、刷新额度、OAuth 刷新和原生重新授权。失败时回读 CPR 的实际状态，不自动清理、替换或迁移凭据。

评审后再确定：选择 A / B1 / B2 / C1 / C2 / D 中的哪些模块；接一个实例还是多个；是否允许临时 AT-only；是否允许解除代理后直连；哪些动作需要批量。未选的模块不应出现在界面或启用对应写入路由。
